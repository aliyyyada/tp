# Данные, обучение и критерий качества

## Что означает «больше 90%»

Для проекта основной критерий — **более 90% полностью верных полей** на независимых документах. Это не средняя confidence OCR и не 1-CER. Номер `60205.00033`, в котором неверна одна цифра, считается неверным полем целиком. Отдельно проверяются длинные описания, числа/нормы, документы, оборудование и правильность связей. Проверяются также пустые ячейки: лишний текст — ошибка. Не допускается улучшать процент исключением трудных полей.

В `evaluate` добавлены `target_exact_cell_accuracy=0.9` и `target_met`, причём требуется строго больше указанного порога. Если reference покрывает не все cells, результат относится только к поднабору. Небольшой контрольный набор на Пример.pdf не является независимым тестом, не содержит всех пустых ячеек и требует проверки технологом.

Без обучения можно улучшать выравнивание, разделение строк, подавление фона до CLAHE, отдельные алфавиты, выбор готового распознавателя и сверку со справочниками. Но достижение 90% для этой рукописи не подтверждено. Разрешать автозамену номера/нормы только по сходству с эталоном нельзя. Лучше сохранять предложение исправления и исходный текст, не затирая его.

## Подавление просвечивания

`--ink-filter --ink-min-contrast 18` оставляет локально тёмные штрихи. Дополнительно `--ink-min-saturation 0..255`, `--ink-max-value 0..255`, `--ink-hue H1 H2` (H=0..179, диапазон может переходить через 0). Фильтр применяется к цветному исходнику до CLAHE; исходные ячейки сохраняются как `crops/raw_*.png`.

Насыщенность сама по себе ненадёжна: бумага цветная, а полезный карандаш может быть серым. Если лицевой и обратный текст имеют одинаковый цвет/темноту, порог не способен их различить. Жёсткая фильтрация удаляет и бледные полезные буквы. Поэтому фильтр включается явно, а не скрыто по умолчанию. Проверять надо и сохранность полезного текста, и ложные срабатывания на пустых областях.

На 73 прежних контрольных ячейках:

| CLAHE + EasyOCR | CER | WER | Полностью совпавшие ячейки |
|---|---:|---:|---:|
| Без фильтра | 21.91% | 67.94% | 39.73% |
| Минимальный локальный контраст 18 | 22.18% | 71.76% | 47.95% |
| Минимальный локальный контраст 30 | 21.91% | 77.10% | 47.95% |

Фильтрация помогла некоторым полям, но не дала общего улучшения CER/WER. Не выдавать это за достижение 90%.

## Формат данных для обучения строк

Рекомендуется дообучать компактный распознаватель последовательностей (CRNN/CTC с кириллическими весами), а не учить с нуля всю страницу. Одна картинка — одна строка, не весь лист. Размечать текст по исходнику, а не принимать OCR без проверки.

```text
dataset/
  lines/D001_L001.png
  lines/D001_L002.png
  labels.jsonl
```

Пример JSONL (каждый объект — отдельная строка файла):

```json
{"image":"lines/D001_L001.png","text":"Транспортирование материала","document_id":"D001","writer_id":"W01","field_type":"content","split":"train"}
{"image":"lines/D002_L001.png","text":"60205.00033","document_id":"D002","writer_id":"W02","field_type":"document","split":"validation"}
```

- PNG без потерь, цветной/серый исходник с полями 5–15 пикселей. Хранить исходное разрешение и отдельно готовить модельный размер.
- Включить кириллицу, цифры, десятичные запятые, точки, дефисы, косые черты, обозначения оборудования, разные размеры и авторов.
- Сохранить ведущие нули и пунктуацию, согласовать правила для неразборчивого текста и переносов. Неразборчивое нельзя размечать догадкой.
- Делить **по документам, а желательно и по авторам**, например 80/10/10. Строки/аугментации одного исходного документа не должны попадать в train и test одновременно.
- Синтетический чертёжный шрифт с шумом/просвечиванием — дополнение к настоящим строкам, не замена. Данные независимого теста не использовать для настройки порогов.

Ориентиры, не гарантированный минимум: 500–1000 строк для пилота; 3000–10000 разнообразных строк для первого серьёзного дообучения. Четырёх листов Пример.pdf недостаточно для оценки обобщения. Объём надо уточнять по кривой качества и представленности букв/авторов/полей.

## Цифры и приложенный MNIST-блокнот

В блокноте Dense 784→784→200→10, ReLU/ReLU/Softmax. Он классифицирует одну картинку 28×28 в один из классов 0..9. Указанная тестовая точность — 97.42% на MNIST; сохранённых обученных весов в ipynb нет. Графики/логи обучения не позволяют восстановить веса.

Модель не знает пустые ячейки, запятые и дефисы, не делит склеенные цифры и не читает `6000` целиком. Простое уменьшение всей ячейки до 28×28 разрушает число. Высокая точность на MNIST не подтверждает точность на ГОСТ-рукописи. Даже 99% на каждой цифре даёт только около 90.4% полностью верных десятизначных чисел при условной независимости ошибок, без учёта сегментации.

Для отдельного классификатора нужен набор настоящих отдельных цифр: ориентир для пилота 200–500 примеров на класс (2000–5000 всего), разные документы/авторы/контраст; отдельно примеры пустоты, шума и разделителей для проверки отказов. Предпочтительнее небольшая CNN. Для целых числовых строк с запятыми/дефисами лучше CTC-распознаватель: не нужно разрезать каждую цифру.

### Экспорт весов из живого блокнота

После обучения, пока переменная `model` существует, выполните в блокноте:

```python
import numpy as np
w1, b1, w2, b2, w3, b3 = model.get_weights()
np.savez_compressed("mnist_dense.npz", w1=w1, b1=b1, w2=w2, b2=b2, w3=w3, b3=b3)
```

Скачайте NPZ из той среды и перенесите на офлайн-ПК. Альтернатива для сохранённого `.keras` — `tools/export_mnist_weights.py`, который выполняется в среде с Keras, где модель уже работала. Сам пользовательский ipynb не публикуется: в нём есть личные пути и выводы Colab.

В проекте можно проверить **одну вручную выделенную цифру**:

```bat
.venv\Scripts\python -m routeocr digit digit.png --weights mnist_dense.npz -o candidate.json
```

Результат только кандидат с `needs_review=true`; он не заменяет значения OCR автоматически. Для применения к числам из таблицы нужен отдельный тест сегментации и классификации. NPZ проверяется по форме массивов, pickle отключён. На ПК распознавания используются уже включённые NumPy/OpenCV, TensorFlow не нужен.

## Ресурсы и сроки

GTX1070 8 ГБ подходит как стартовая карта для дообучения небольшой CNN/CRNN. Начинать с FP32, высоты строк 32–64, небольших batch (например 4–16), подбирая по памяти; при необходимости накапливать градиенты. Здесь скорость/память на GTX1070 не измерялись, конкретный batch не гарантирован. Совместимость PyTorch/CUDA/Pascal нужно проверить на целевом ПК; в архиве CPU-сборка, GPU-скрипты выбирают torch 2.5.1 + CUDA 11.8.

Для ориентира планировать несколько часов на один компактный тренировочный прогон, возможны сутки и более при длинных строках/многих эпохах. Это оценка планирования, а не замер. Точное время оценить по первым 100–200 batch на реальной карте. Несколько прогонов и подбор параметров увеличивают сроки.

Разметка часто дольше обучения: при 20–60 сек на строку 1000 строк — примерно 6–17 часов чистой работы, плюс нарезка и проверка. Для нескольких тысяч строк — несколько рабочих дней и больше. Результат после пилота решает, стоит ли расширять набор.

Современный TensorFlow 2.11+ не предоставляет штатную CUDA-поддержку в native Windows. Поэтому установка последнего TensorFlow из блока pip в ipynb не задействует GTX1070 автоматически. Для проекта предпочтительнее использовать уже выбранный PyTorch; для NumPy-инференса MNIST GPU вообще не нужен.
